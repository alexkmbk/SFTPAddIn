# SFTPAddIn

Внешняя компонента Native API для 1С:Предприятия 8.3.26 на Windows.
C++17, CMake, MSVC, libssh2 и OpenSSL. Поддерживаются x86 и x64,
работа в настольном клиенте и на сервере 1С. Все вызовы синхронные.

Версия 0.2.0 изменяет контракты `GetFile` и `MoveFile`; совместимость с 0.1.0
не сохраняется. Добавлены `Stat`, `LastErrorDetails`, `PutFile` и `PutFiles`.

## Методы

| Метод | Результат и поведение |
| --- | --- |
| `Connect(Host, Port, UserName, Password, HostKeyFingerprint = "")` | `Истина` после подключения и парольной аутентификации. Повторный вызов закрывает прежнее соединение. |
| `Disconnect()` | Закрывает соединение. Повторный вызов допустим. Возвращает `Истина`. |
| `ListFiles(RemoteDirectory)` | Строка JSON: файлы, каталоги и ссылки непосредственно в указанной папке. Без рекурсии; `.` и `..` исключены. |
| `GetFile(RemotePath, LocalFullPath, FailIfExists = False)` | Скачивает один файл в заданный полный абсолютный локальный путь, включая имя. Создаёт родительские папки. Возвращает сохранённый путь. `Истина` запрещает перезапись. |
| `GetFileBinData(RemotePath)` | Возвращает `ДвоичныеДанные`, включая корректный результат для пустого файла. |
| `MoveFile(RemotePath, TargetPath, Overwrite = False)` | Перемещает и/или переименовывает файл на том же сервере. Второй аргумент — полный конечный путь. Возвращает `Истина`; по умолчанию перезапись запрещена. |
| `DeleteFile(RemotePath)` | Удаляет конкретный удалённый файл. Возвращает `Истина`. |
| `Stat(RemotePath, FollowSymlinks = False)` | Сведения об одном пути как JSON-объект с `exists` и атрибутами. По умолчанию возвращает сведения о самой ссылке. |
| `PutFile(LocalFullPath, RemoteFullPath, DeleteSource = False, NewerOnly = False)` | Отправляет один локальный файл. `Истина` — передан, `Ложь` — пропущен по `NewerOnly`; при ошибке исключение. Оба пути включают имя файла. |
| `PutFiles(LocalDirectory, RemoteDirectory, DeleteSource = False, NewerOnly = False)` | Отправляет непосредственные файлы каталога с сохранением имён, без рекурсии. Возвращает JSON с результатом. При первой ошибке останавливается. |

Удалённые пути передаются буквально, без масок `*`/`?`, shell-команд и подстановок.
Рекомендуются полные пути с `/`. Корневая папка определяется SFTP-сервером,
в том числе его chroot-настройками.
У каждого экземпляра компоненты собственное соединение.

В `GetFile` второй аргумент всегда означает полный путь файла. Каталог по
существованию, расширению или последнему разделителю не угадывается. Локальное имя
может отличаться от серверного. Путь должен быть абсолютным и включать допустимое
имя Windows; маски, имена устройств, альтернативные потоки NTFS и каталог вместо
имени файла не принимаются.

`GetFile` скачивает во временный файл в целевой папке, сбрасывает данные на диск
и заменяет конечный файл только после успешного скачивания. Существующий файл
по умолчанию перезаписывается. При `FailIfExists = Истина` конечная операция
Windows выполняется без разрешения замены: файл, созданный другим процессом
во время скачивания, также не будет затёрт. При ошибке временный файл удаляется; прежний конечный файл
сохраняется. После аварийного завершения процесса временный файл может остаться.

`MoveFile` требует существования родительского каталога назначения и не создаёт
удалённые каталоги. При `Overwrite = Истина` используется серверное расширение
`posix-rename@openssh.com`. Если сервер не объявил или отклонил его поддержку,
возвращается ошибка без предварительного удаления назначения. Перенос между
файловыми системами может быть отвергнут сервером; копирование с удалением не
эмулируется. Для обычного перемещения используются гарантии SFTP-сервера.

### Отправка файлов

`PutFile` и `PutFiles` требуют существующего удалённого каталога. Локальные пути
должны быть абсолютными. `PutFiles` сначала получает и сортирует список имён;
новые файлы, появившиеся после перечисления, в текущую пачку не включаются.
Подкаталоги и ссылки/reparse points пропускаются. `PutFile` также не принимает
ссылки или каталог вместо исходного файла. Удалённый конечный файл-ссылка
или каталог вместо файла отклоняется.

Содержимое передаётся порциями по 64 КиБ в уникальный временный файл `.sftp-*.tmp`
в целевом каталоге. Проверяются количество переданных байтов и размер на сервере,
сохраняется время изменения исходника, затем файл закрывается и переименовывается
в окончательное имя. Для замены существующего файла требуется
`posix-rename@openssh.com`; удаление старого файла перед заменой не применяется.
Если во время отправки нового файла конечное имя занял другой процесс,
переименование может завершиться ошибкой; конкурентный файл не удаляется.
При ошибке временный файл удаляется по возможности. При потере соединения
или аварийном завершении процесса он может остаться.

`NewerOnly = Истина` сравнивает время изменения локального и удалённого файла
в UTC с точностью до секунды. Если удалённого файла нет или локальный строго
новее, выполняется отправка. При равном времени или более новом удалённом файле
отправка пропускается; размер и содержимое при этом не сравниваются.
Если сервер не вернул время существующего файла, возникает ошибка.
Время сохраняется и при `NewerOnly = Ложь`. Поддерживается диапазон времени
SFTP v3: 1970–2106. Проверка времени и замена не образуют транзакцию с другими клиентами.

`DeleteSource = Истина` удаляет локальный исходник только после подтверждённого
завершения передачи и окончательного переименования. Пропущенный исходник
сохраняется. На время отправки файл открыт с запретом записи и удаления другими
процессами. Если удалить исходник после отправки не удалось, метод вызывает
исключение: удалённый файл уже существует, локальный исходник остаётся.

Результат `PutFiles` содержит массивы `uploaded`, `skipped`, `pending`
с именами файлов без каталога. При успехе `pending` пуст. Пустой локальный
каталог допустим, но удалённый каталог проверяется и в этом случае.
При первой ошибке метод останавливается; выполненные операции не откатываются.
В `LastErrorDetails.upload` сохраняются эти же массивы, `failedFile`, полный
`localPath` и `remotePath` проблемного файла, `temporaryPath` (если очистка не
подтверждена), `transferCompleted` и `sourceDeleted`. Проблемный файл не входит
в `pending`; там только ещё не обработанные файлы. Если отправка завершена,
а удаление исходника не удалось, имя также входит в `uploaded` и
`transferCompleted = true`. При потере ответа на окончательное переименование
`outcomeUnknown = true`, исходник сохраняется; перед повтором нужно проверить
состояние на сервере. Диагностику следует прочитать до следующего метода,
включая `Disconnect`.

```bsl
Передан = SFTP.PutFile("C:\EDI\out\order.xml", "/inbox/order.xml", Ложь, Истина);
РезультатJSON = SFTP.PutFiles("C:\EDI\out", "/inbox", Истина, Истина);
```

Проверены файлы размером 100 МиБ. `GetFile` пишет потоками по 64 КиБ;
`GetFileBinData` хранит файл в памяти и затем копирует в память менеджера 1С,
поэтому расход памяти может превышать удвоенный размер файла. Искусственного
лимита 100 МиБ нет, но действуют ограничения памяти процесса и длины `VTYPE_BLOB`.
На x86 доступной памяти заметно меньше. Размер перед скачиванием сравнивается
с количеством полученных байтов; изменение содержимого без изменения размера
не выявляется. Скачивать следует уже завершённые файлы.

Для вызова на сервере локальные пути и права доступа относятся к серверу и
учётной записи его службы; для клиента — к клиентскому компьютеру и пользователю.
Прямой возврат `VTYPE_BLOB` в веб-клиент Native API не поддерживает.

## Проверка ключа сервера

Пятый параметр `Connect` необязательный. Единственный принимаемый формат —
полная SHA-256-строка WinSCP/PuTTY: `<тип ключа> <число битов> <Base64 SHA-256>`.
Например: `ssh-ed25519 255 <Base64 SHA-256 ключа>`,
`ssh-rsa 2048 <Base64 SHA-256 ключа>` или `ecdsa-sha2-nistp256 256 <Base64 SHA-256 ключа>`.
Варианты Base64 с завершающим `=` и без него принимаются.
Короткий формат `SHA256:…` не поддерживается.
Тип ключа задаётся при согласовании SSH и дополнительно проверяется после него.
Это позволяет выбрать нужный ключ, когда сервер предлагает несколько типов.
Для RSA допускаются подписи RSA SHA-2 с тем же открытым ключом.
Число битов проверяется на корректность записи,
но не сравнивается: Ed25519 может обозначаться как 255 или 256 бит.
MD5-строки WinSCP с отпечатком вида `68:cf:…` не принимаются.
Если отпечаток указан, проверка происходит **до передачи пароля**; несовпадение
закрывает соединение. Пустой параметр отключает проверку подлинности ключа сервера.
Фактический отпечаток доступен через `HostKeyFingerprint` после подключения
в том же полном формате, без завершающего `=`; размер Ed25519 возвращается как 255.
Его отображение само по себе не подтверждает подлинность сервера.
Поддерживается именно аутентификация SSH `password`, без keyboard-interactive/MFA.

## Свойства

| Свойство | Доступ | Описание |
| --- | --- | --- |
| `Connected` | Чтение | У экземпляра открыта SFTP-сессия. Это не активная проверка доступности сервера. |
| `Timeout` | Чтение/запись | Тайм-аут сетевого ожидания в секундах, 1–3600, по умолчанию 30. Применяется также к открытому соединению. |
| `HostKeyFingerprint` | Чтение | Фактический SHA-256 отпечаток в полном формате WinSCP/PuTTY; пустая строка после отключения. |
| `LastError` | Чтение | Текст последней ошибки для явного чтения из 1С после перехвата исключения. |
| `LastErrorDetails` | Чтение | JSON-объект последней ошибки. История не хранится; при отсутствии ошибки — `{}`. |
| `Version` | Чтение | Версия компоненты. |

Тайм-аут ограничивает TCP-подключение и отдельные ожидания SSH/SFTP, а не общее
время передачи файла. DNS-разрешение выполняется Windows и использует системные
тайм-ауты. После транспортной ошибки соединение закрывается; для повтора нужно
снова вызвать `Connect`. Автоматического повторения скачивания, удаления или
перемещения нет.

Неуспешный вызов Native API прерывает выполнение исключением 1С. **Текст причины
нужно явно читать из `LastError`**, а дополнительные сведения — из `LastErrorDetails`:
текст, переданный через `IAddInDefBase::AddError`, не следует ожидать в
`ОписаниеОшибки()` / `ErrorDescription()`. Пример:

```bsl
Попытка
    Путь = Компонента.GetFile("/exchange/report.csv", "D:\Import\report.csv");
Исключение
    ТекстПричины = Компонента.LastError;
    ПодробностиJSON = Компонента.LastErrorDetails;
    Компонента.Disconnect();
    ВызватьИсключение ТекстПричины;
КонецПопытки;
```

**Каждый вызов метода, включая `Disconnect`, очищает предыдущую ошибку в начале
вызова.** При отказе он записывает новую ошибку, при успехе `LastError` пуст,
`LastErrorDetails` равен `{}`. Запись `Timeout` также очищает предыдущую ошибку.
Чтение свойств диагностику не очищает. Поэтому после исключения сначала
скопируйте `LastError` и нужные подробности в переменные 1С, затем вызывайте
`Disconnect` или другие методы. Отдельных `ClearError` и `LastErrorCode` нет.

Поля `LastErrorDetails`: `code`, `message`, `operation`, `remotePath`,
`targetPath`, `localPath`, `sshCode`, `sftpCode`, `systemCode`, `connectionLost`,
`outcomeUnknown`. Неприменимые пути — пустые строки, недоступные числовые коды —
`null`. `connectionLost` означает, что текущая SSH-сессия закрыта как непригодная;
Для отправки дополнительно возвращается объект `upload`, описанный выше.
`outcomeUnknown` указывает, что после потери ответа на удаление/перемещение/публикацию файла сервер
мог уже выполнить операцию. Автоматического повтора нет. При отсутствии памяти
расширенные подробности могут быть недоступны. Коды внутри JSON — диагностика,
а не логин, пароль или ключи доступа.

Категории:
1 — параметры; 2 — нет соединения; 3 — TCP/DNS; 4 — SSH/аутентификация/тайм-аут;
5 — SFTP; 6 — локальная файловая система; 7 — ключ сервера;
8 — память; 9 — внутренняя ошибка. При наличии в описании дополнительно указаны
коды SSH и SFTP. Значения паролей компонента в сообщения не добавляет.

Английские имена методов/свойств регистронезависимы; есть русские псевдонимы
(`Подключить`, `Отключить`, `СписокФайлов`, `ПолучитьФайл`,
`ПолучитьФайлДвоичныеДанные`, `ПереместитьФайл`, `УдалитьФайл`,
`СведенияОФайле`, `ОтправитьФайл`, `ОтправитьФайлы`). Диагностический журнал пока не реализован.

## Формат списка

```json
[
  {
    "name": "report.csv",
    "path": "/exchange/report.csv",
    "type": "file",
    "size": 1024,
    "modifiedTime": 1729000000,
    "permissions": 33188
  }
]
```

`type`: `file`, `directory`, `symlink`, `unknown`. `size` — байты;
`modifiedTime` — Unix time в секундах UTC; `permissions` — числовое поле POSIX
с типом и правами. Отсутствующие атрибуты передаются как `null`.
Результат сортируется по имени в UTF-8. Серверные имена должны быть в UTF-8;
некорректная кодировка вызывает ошибку. Кавычки, обратные слеши и все управляющие
символы JSON экранируются; отдельная JSON-библиотека не используется.

## Stat

`Stat("/incoming/order.edi")` возвращает один объект с теми же полями, что
запись `ListFiles`, и дополнительным `exists`:

```json
{"exists":true,"name":"order.edi","path":"/incoming/order.edi","type":"file","size":1024,"modifiedTime":1729000000,"permissions":33188}
```

При подтверждённом сервером отсутствии пути: `exists = false`, `type = "unknown"`,
размер, время и права — `null`; исключения нет. Отказ доступа, тайм-аут, отсутствие
соединения и другие ошибки вызывают исключение и заполняют `LastError`.
`Stat(path, Ложь)` возвращает сведения о самой символической ссылке,
`Stat(path, Истина)` — о её цели. Ссылка на отсутствующую цель существует при
`FollowSymlinks = Ложь`, но возвращает `exists = false` при `Истина`.
Метод не скачивает данные и не резервирует путь для последующего скачивания.

## Сборка

Нужны Visual Studio 2022 с Desktop development with C++, Windows SDK,
CMake 3.24+ и vcpkg. Версии зависимостей закреплены baseline в `vcpkg.json`.
Пример настройки пути к установленному vcpkg:

```powershell
$env:VCPKG_ROOT = 'C:\tools\vcpkg'
cmake --preset windows-x64
cmake --build --preset windows-x64
ctest --preset windows-x64

cmake --preset windows-x86
cmake --build --preset windows-x86
ctest --preset windows-x86

powershell -NoProfile -File scripts/package.ps1
```

Компонента остаётся DLL для загрузки платформой. libssh2 и OpenSSL включаются
в неё статически; runtime MSVC — `/MT` (Release) / `/MTd` (Debug).
Используются `x64-windows-static` и `x86-windows-static`, а не варианты `static-md`.
Сжатие zlib отключено. Системные библиотеки Windows остаются динамическими.
Сборка не требует изменения глобального `vcpkg integrate install`.
Фиксированный путь к vcpkg в переносимые файлы проекта не зашит.
Через `vcpkg-configuration.json` используется локальный overlay `ports/libssh2`:
libssh2 1.11.1 с исправлениями освобождения ресурсов AES-GCM и OpenSSL 3 ECDH.
Для воспроизводимой сборки этот каталог также нужен. Глобальный порт vcpkg
не изменяется; зависимости и CRT остаются статическими.

Артефакты: `build/windows-x64/Release/SFTPAddIn_x64.dll`,
`build/windows-x86/Release/SFTPAddIn_x86.dll`, `dist/SFTPAddIn-Release.zip`.
ZIP содержит `MANIFEST.XML`, `info.xml`, `VerInfo.txt`, обе DLL и уведомления
о лицензиях зависимостей. Версия в метаданных берётся из CMake.
Документация и пример BSL остаются в репозитории и в ZIP не включаются.
Для статической линковки при распространении нужно сохранять эти уведомления.

## Подключение из 1С

```bsl
// ZIP читается как двоичные данные и помещается во временное хранилище.
Местоположение = ПоместитьВоВременноеХранилище(Новый ДвоичныеДанные(ПутьКПакетуZIP));
Если Не ПодключитьВнешнююКомпоненту(
    Местоположение, "SFTPAddIn", ТипВнешнейКомпоненты.Native) Тогда
    ВызватьИсключение "Не удалось подключить SFTPAddIn";
КонецЕсли;
Компонента = Новый("AddIn.SFTPAddIn.SFTP");
Компонента.Connect(АдресСервера, 22, Пользователь, Пароль, ОжидаемыйОтпечаток);
Данные = Компонента.GetFileBinData("/exchange/report.csv");
Путь = Компонента.GetFile("/exchange/report.csv", "D:\Import\report.csv");
Компонента.Disconnect();
```

В ZIP платформа выбирает нужную архитектуру по манифесту. ZIP можно также
поместить в общий макет конфигурации типа «Внешняя компонента»/«Двоичные данные»
и передать строку `ОбщийМакет.ИмяМакета`. Путь к ZIP на диске напрямую не передаётся.
Для прямого подключения отдельной DLL используйте её полный путь вместо
`Местоположение`; разрядность DLL должна совпадать с процессом, выполняющим вызов.
Пример с обработкой ошибок и чтением JSON: [examples/SFTP.bsl](examples/SFTP.bsl).

## Проверки

CTest проверяет UTF-8/UTF-16, экранирование JSON, Windows-имена, отпечатки и
оболочку Native API с имитацией менеджера памяти 1С (включая ошибки выделения).
Интеграционный тест поднимает временный SFTP-сервер только на `127.0.0.1`:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r tests/requirements.txt
.\.venv\Scripts\python.exe tests/integration.py build/windows-x64/Release/native_host.exe build/windows-x64/Release/SFTPAddIn_x64.dll
.\.venv\Scripts\python.exe tests/integration.py build/windows-x86/Release/native_host.exe build/windows-x86/Release/SFTPAddIn_x86.dll
```

Проверяются 100 МиБ в памяти и на диске, пустые файлы, Unicode, корректность
JSON стандартным парсером Python, побайтовое совпадение, создание папок,
перезапись, неверный пароль/отпечаток, тайм-аут, восстановление подключения,
ошибка в середине передачи, сохранность прежнего файла и отсутствие временных
файлов после ошибки, перемещение и удаление.
Дополнительно выполнен тест в настоящем клиенте 1С 8.3.26.1581 (x86):
подключение отдельной DLL и ZIP через временное хранилище, список JSON,
возврат типа `ДвоичныеДанные`, пустой файл,
сохранение на диск, перемещение и удаление. Тест создаёт отдельную временную
пустую базу, не меняет существующие базы и регистрацию COM:

```powershell
.\.venv\Scripts\python.exe tests/platform_integration.py 'C:\Program Files (x86)\1cv8\8.3.26.1581\bin\1cv8.exe' dist/SFTPAddIn-Release.zip
```

Нужен установленный клиент 1С с доступной лицензией.

В отдельной тестовой базе также выполнен тест
через MCP-инструмент `Execute` в серверном контексте HTTP-сервиса 1С 8.3.26.1581
(Apache x86): ZIP, JSON, двоичные данные, пустой файл, скачивание 100 МиБ
в память и на диск, перемещение, удаление и ошибка отсутствующего файла.
Содержимое записанных файлов проверено Python. Записи базы тест не изменяет.
Повторный запуск требует явного разрешения владельца соответствующей базы:

```powershell
# Запустите локальную веб-публикацию заранее.
# При необходимости пароль HTTP берётся из переменной MCP_HTTP_PASSWORD.
.\.venv\Scripts\python.exe tests/mcp_integration.py 'http://127.0.0.1:8081/test_base/hs/mcp/' dist/SFTPAddIn-Release.zip --user '<HTTP_USER>' --temp-root 'C:\SFTPTests\temp'
```

Работа в отдельном процессе сервера кластера `rphost`, клиенте 1С x64
и совместимость с рабочим SFTP-сервером пока не проверялись.
