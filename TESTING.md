Локальный SFTP-сервер использует пароль, временный ключ и данные, слушает только
127.0.0.1. Проверены неправильный пароль и отпечаток, отсутствие обязательной
проверки отпечатка при пустом параметре, Unicode, JSON стандартным парсером Python,
пустой файл, создание папок, перезапись локального файла, ошибка в середине чтения,
сохранение прежнего файла и удаление временного, тайм-аут и повторное подключение,
перемещение/удаление и отказ перезаписи при перемещении на тестовом сервере.

В реальном клиенте 1С проверены загрузка компоненты, чтение JSON штатным парсером,
фактический тип `ДвоичныеДанные`, его размер и побайтовая запись в файл,
скачивание пустого файла, GetFile с полным локальным путём и созданием папки,
переименование при MoveFile и DeleteFile, Stat отсутствующего файла.
Native API вызывает исключение при запрете перезаписи, после чего тест явно
читает текст и подробности из LastError/LastErrorDetails до Disconnect,
проверяет очистку свойств после отключения и сохранность скопированных переменных.
На ErrorDescription как источник
текста ошибки компоненты тест не полагается.
Использована отдельная автоматически созданная временная пустая база.

Дополнение от 2026-10-24: в реальном клиенте 1С x86 проверены `PutFile`,
пропуск по `NewerOnly` с сохранением исходника, `PutFiles` с `DeleteSource`
и чтение результата штатным JSON-парсером. На обеих архитектурах проверены
ошибки отправки и частичный результат пачки. Неизвестный результат после
тайм-аута переименования не приводит к удалению исходника.

В Debian OpenSSH переданы копии четырёх файлов из `data/testData`, проверены
SHA-256 содержимого и время изменения, замена существующего файла, пропуск
неизменённого файла и удаление локальных копий. Тестовые удалённые файлы
удалены из уникального каталога; исходный `/files` и `data/testData` сохранены.
Для повторения с отдельным SFTP-сервисом в Debian WSL укажите собственные
имя пользователя и пути к локальным файлам пароля и открытого ключа сервера:

```powershell
.\.venv\Scripts\python.exe tests\wsl_integration.py build\windows-x64\Release\native_host.exe build\windows-x64\Release\SFTPAddIn_x64.dll --user '<SFTP_USER>' --password-file '/path/to/test-password' --host-key-file '/path/to/ssh_host_ed25519_key.pub'
.\.venv\Scripts\python.exe tests\wsl_integration.py build\windows-x86\Release\native_host.exe build\windows-x86\Release\SFTPAddIn_x86.dll --user '<SFTP_USER>' --password-file '/path/to/test-password' --host-key-file '/path/to/ssh_host_ed25519_key.pub'
```

По dumpbin обе DLL импортируют CRYPT32.dll, WS2_32.dll, KERNEL32.dll,
USER32.dll и ADVAPI32.dll. Дополнительных сторонних DLL в поставке нет.

Тест через COMConnector не выполнен: установленная регистрация библиотеки типов
возвращает TYPE_E_LIBNOTREGISTERED. Регистрация системы не менялась;
успешный клиентский тест выполняется через 1cv8.exe и не использует COMConnector.

В отдельной тестовой базе выполнен тест
через локальную HTTP-публикацию, MCP-инструмент `Execute`.
HTTP-сервис исполняет код на серверной стороне платформы 1С через Apache x86.
Результат: `success=true`, `version="0.2.0"`, `binarySize=300123`, `largeBinarySize=104857600`.
Проверены ZIP, JSON, фактический тип BinaryData, пустой файл, обе функции
скачивания (включая 100 МиБ), создание вложенной папки, перемещение, удаление
и обработка отсутствующего файла. Python проверил содержимое файлов побайтово.
Дополнительно проверены новый контракт GetFile, запрет перезаписи,
Stat существующего и отсутствующего файла, чтение LastError/LastErrorDetails
до Disconnect и автоматическая очистка после него. Из свойства компоненты прочитан исходный
текст: `Open remote file failed (SSH -31, SFTP 2): Failed opening remote file`.
Временные файлы удалены, записи базы и её конфигурация не менялись.

Повторение проверок описано в README.md. Проверки в отдельном процессе кластера
1С `rphost`, в клиенте 1С x64 и на рабочем SFTP-сервере остаются отдельными этапами.
